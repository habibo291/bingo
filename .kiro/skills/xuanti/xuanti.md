# xuanti

`xuanti` 是一个 **选题生成 skill**。

它的任务不是替用户写完整文案，也不是替用户决定这条最终拍什么，而是：

> **根据一家店的素材，发散出一批可拍、可写、可继续展开的选题。**

用户自己选题，后续再手动调用 `kaitou` / `wenan` 等模块继续创作。

---

## 核心定位

**`xuanti` 只负责出题，不负责代替用户做判断。**

- 它负责把素材变成多条不同方向的选题
- 它负责把选题按类别拉开，而不是只出同一路子
- 它不负责说"最推荐哪一个"
- 它不负责直接进入完整文案生成
- 它不应该把"好看的一句话"误当成"选题"

`xuanti` 更像：选题搭子 / 题库生成器 / 创作前的发散器。
不是：总编 / 文案生成器 / 自动编排器。

---

## 1. 素材来源与输入识别

凡涉及 Obsidian 的读写，都通过 **Obsidian CLI** 操作。不要假设 Obsidian 内容已在上下文中，也不要绕过 CLI。

### 1.1 素材来源优先级
1. 用户当前给的大段素材文本
2. Obsidian `4.创作/1.素材库/` 中的对应笔记
3. `4.创作/ip/账号IP创作原则.md`（IP 风格校准）

**默认完全不读**：`4.创作/2.选题/`、`4.创作/6.策略判断/`、`4.创作/7.复盘/`。
只有当用户明确说"参考策略 / 参考上次 / 参考之前的题 / 别和以前重复"等，才通过 CLI 读取。

这样做是为了：
- 避免被旧题驯化成只会一种路子
- 让"越用越懂你"靠 user-profile，不靠外部日志

### 1.2 用户输入识别

#### A. 店名直读模式
例如：
- `阿茹娜aruna的选题`
- `给我北疆北的选题`
- `巴巴汗选题`
- `三亚选题`

动作：
1. 识别店名或主题名
2. 在 `4.创作/1.素材库/` 范围内查找对应笔记
3. 精确匹配优先；若无，再做标准化模糊匹配
4. 模糊匹配容忍：中英文混写、空格、大小写、标点、音译写法、常见手误
5. 单一高置信结果直接用；多结果让用户选；零结果提示补充

注意：触发不要求带"店"字，只要整体表达明显是"对象 + 选题"意图就命中。对象可以是店、地点、旅行主题、其它素材库主题。

#### B. 直接文本模式
例如：
- `选题 这家店主要卖哈萨克特色美食……`
- `根据这段素材帮我出18个选题：……`

动作：直接用用户文本作为主素材；如果文本里点名某店，素材库笔记作为补充。

### 1.3 用户档案（写前必读）
读完素材后，先读 `references/user-profile.md`。按里面记录的偏好路子、母题、切口、被否方向执行。
档案为空（首次使用）就按通用规则写，并主动观察这一轮反馈。

## 2. 路子选择（4 选 1）

> 注意：路子决定**从哪个角度切入**。
> 母题拉开（§4）是所有路子都要做的底层动作，不是路子之一。

### 2.1 4 种路子

1. **母题先行**：先拉开 5-7 个不同母题，再在每个母题下展开具体题
2. **冲突先行**：先抓最有张力的矛盾、误解、反差，再围绕这个冲突往外扩
3. **人物先行**：先找老板、员工、顾客、自己，再从"人"往外长题
4. **反重复先行**：先避开旧路子，再有意识地逼自己开新题

### 2.2 自动判定表

| 素材特征 | 默认路子 |
|---|---|
| 信息点多但没有明显主线 | 母题先行 |
| 有强反差、误解、价格冲突 | 冲突先行 |
| 老板 / 员工 / 顾客有鲜明故事 | 人物先行 |
| 同类店写多了、用户嫌旧 | 反重复先行 |

如果用户档案里 `偏好路子` 已经有 Top 1，且当前素材也适用，则优先用偏好路子。

### 2.3 用户显式指定
- `巴巴汗选题 母题先行` / `冲突先行` / `人物先行` / `反重复先行` → 严格按指定
- `换个路子 / 用别的路子 / 试试其他路子` → 不要让用户记路子名，主动给 2-3 个可替换路子，每个一句话说明差别

### 2.4 输出开头必带

```
本轮路子：xxx
判定理由：一句话
```

## 3. 拆素材（5 层）

写选题前，先在内部识别这几层资源：

- **事实层**：客观提供什么（菜、空间、套餐、体验、人物、故事）
- **反差层**：误解 / 预期落差 / "我原本以为……" / 价格与完成度反差
- **人物层**：老板 / 主厨 / 服务员 / 顾客 / 父母 / 普通人 / 自己
- **文化层**：新疆语境 / 本地经验 / 民族文化 / 外地人误解 / 地域生活逻辑
- **情绪层**：惊喜 / 打脸 / 温暖 / 理解 / 心酸 / 参与感 / 被邀请感 / 生活气
- **延展层**：除了"吃"和"推荐"还能讲什么——关系 / 生活方式 / 城市观察 / 文化纠偏 / 普通人的体面与分寸

重点不是把素材总结一遍，而是看清：**这家店到底能长出哪些不同方向的题。**

---

## 4. 母题拉开（所有路子都要做）

正式生成前，先在内部拉开 **5-7 个母题**。母题指更上层的选题大方向，例如：
- 早餐文化 / 老店存在感 / 经营哲学 / 消费信任 / 地域生活方式 / 城市节奏与普通人日常

### 4.1 母题分布
- **60% 左右**围绕素材里最强母题展开
- **40% 左右**主动跳出最强母题，开外圈路径

外圈路径优先考虑：地域生活 / 城市观察 / 早餐节奏 / 老店情感 / 普通人需求 / 信任关系 / 生活方式判断。

### 4.2 母题拉开的 3 个内部检查
1. 只看题目不看分类，是否仍能感觉是不同路子？
2. 这些题是否能被一句更大的话轻易全部概括掉？（能就是太窄）
3. 是否有足够一部分题，明显跳出了素材里最强的那个核心点？

如果大多数题都能被同一个母题罩住，重新拉。

---

## 5. 18 题输出

### 5.1 默认分类（6 类各 3 题）
1. **认知翻案类**
2. **人物故事类**
3. **价格价值类**
4. **文化体验类**
5. **关系情绪类**
6. **生活方式 / 城市观察类**

如果素材明显更偏某一路，可适度倾斜，但不要 18 个挤在同一气质里。

### 5.2 命中门槛（强制）

18 题里至少 **12 题**满足"好选题 5 条"中的 3 条：

1. **有现实落点**：能落到一家店、一次体验、一个人物、一个细节
2. **有具体人物**：不只是抽象观点
3. **有细节能撑住**：后续手写时有证据
4. **有误解 / 反差 / 转折**：能形成继续讲下去的张力
5. **有账号自己的视角**：新疆 / 本地 / 女性 / 人情味 / 文化解释 / 生活理解

不满足的题在出之前就替换掉，不要凑数。

### 5.3 默认避免的题感

- 纯种草标题
- 纯菜品堆砌
- 装修打卡感
- 空洞情绪话题
- 放到任何账号都能成立的泛题
- 用金句冒充题目
- 把漂亮话当内核
- 强行上价值但没有素材承接

典型空题：
- "这家店太治愈了"
- "一家很有氛围感的店"
- "成年人都该懂的体面"
- "一次难忘的文化体验"

### 5.4 输出格式

```
本轮路子：xxx
判定理由：……

━━━━━━━━━━━━━━━━━━━━
一、认知翻案类
━━━━━━━━━━━━━━━━━━━━

1. 题目
内核：……

---

2. 题目
内核：……

---

3. 题目
内核：……

━━━━━━━━━━━━━━━━━━━━
二、人物故事类
━━━━━━━━━━━━━━━━━━━━

4. 题目
内核：……

---

（以此类推到 18）
```

格式硬规则：
- 每题之间用 `---` 分隔，分隔线上下空行
- 每个大类用 `━━━━━━━━━━━━━━━━━━━━` 包裹
- 每题先题目，下一行 `内核：……`
- 内核不是文案，不写成完整口播；说清这个题在讲什么、为什么值得做

### 5.5 风格目标（应该优先生成的题感）

- 借店讲人
- 借体验讲生活
- 借细节讲文化
- 借反转讲判断
- 借真实感受讲理解

---

## 6. 出题前自检（gate）

输出前过 3 问，任一不过关重写：

1. 18 题去掉分类，能不能一眼看出不同路子？
2. 有没有题换一家店也照样成立？（有就替换）
3. 是不是大多数题都能被同一句话罩住？（是就重新拉母题）

---

## 7. 学习与进化（越用越懂你的核心机制）

**`xuanti` 学的是用户的判断标准，不是外部日志本身。**

### 7.1 写前必读
`references/user-profile.md`（固定字段，记录偏好路子、母题、切口、被否方向、禁用句式）。

### 7.2 写后必更新
出现以下情况，立刻在档案里追加：
- 用户明确说哪题最好
- 用户明确说哪类不行 / 太空 / 太旧 / 太像以前 / 太窄 / 像标题党 / 只有话术没承接
- 用户说"这个路子对了""以后按这个来"
- 用户最终挑了某几题进入下一步（能看出取舍逻辑）

### 7.3 三个学习文件分流
- `references/user-profile.md`：当前偏好快照（写前对照）
- `references/evolution.md`：稳定命中的方法（"以后怎么做"）
- `references/anti-patterns.md`：被反复否的雷区（"以后不怎么做"）

连续多次稳定出现的经验，再合并进 `references/style-guide.md`。

### 7.4 续轮原则（默认）
- 常规续轮：主轴 60-70% + 异质 30-40%
- 用户说"再来一轮 / 再换一轮 / 继续" = 常规续轮
- 用户说"再发散 / 开脑洞 / 别再走原路 / 试试其他路子" = 进入受控发散，主轴降到 30-40%

### 7.5 自然反馈直接调下一轮
以下表达默认是"马上调下一轮"，不要先转外部复盘：
- `第四题最好` / `这种的不行` / `这次太窄了` / `这个格式太密` / `太像以前`
- `这个路子比上一轮好很多` / `别再提钱包这个了`

处理方式：
1. 判断用户在放大什么、否定什么、要避开什么
2. 直接改下一轮的路子、母题分布、切口分配、表达密度
3. 同步更新 user-profile.md

### 7.6 受控发散触发
- 用户说"还是不对 / 都差不多 / 太像以前 / 太窄了"
- 连续几轮在同一审美路径打转
- 进入后：换母题 / 换人物 / 换误解 / 换情绪 / 换落点，明显换脑路而不是换词
- 仍保留少量与原方向连续的版本，避免整轮断掉

### 7.7 学的是判断标准，不是表层句子
学：用户更常选哪类路子、哪类题感、哪类切口、哪类素材适合什么母题。
不学：某句好听的话、某个偶然被选中的标题句式、某条原话。

### 7.8 防止越学越死
- 已验证偏好作为主轴（60-70%），始终保留新切口、新母题、新落点（30-40%）
- 连续 2 轮同腔调，主动拉开变化
- 即使用户最近偏爱某种路子，也偶尔给少量异质版本试探新空间

## 8. 默认不写回 Obsidian

`xuanti` 默认只读、不写。
默认不要把 18 个选题自动写回 `4.创作/2.选题/`、`4.创作/7.复盘/` 或任何 Obsidian 笔记。

只有用户明确说：
- `记下这轮选题`
- `把这轮选题存到 Obsidian`
- `保存成选题笔记`

才允许进入写回动作（仍走 Obsidian CLI）。

---

## 9. 素材太薄时的处理

如果素材太少，不要立刻输出空泛题。
1. 先尽量从当前素材里提取人物、误解、细节、感受
2. 仍明显不足时，再补 1-2 个关键问题，不要连珠炮
3. 不要为了凑 18 个，硬出一堆没有承接点的空题

优先补问的方向：
- 这家店最打动你的细节是什么
- 有没有具体的人或一句话
- 你最意外的是哪一点
- 这家店最容易被误解的地方是什么

---

## 10. 输出尾巴（固定 4 项）

每轮 18 题后必须固定附上下面 4 句，按原样输出，不得改写、删减、追加第 5 项。

```
1. 你挑一个题，我继续给你配结构。
2. 如果你想更偏人物 / 文化 / 价格 / 关系，我可以再重开一轮。
3. 如果你怕和旧题太像，我可以按"避开旧路子"再出一轮。
4. 如果你想试试其他路子，我可以换成 冲突先行 / 人物先行 / 反重复先行 重开。
```

硬规则：
- 必须出现在结尾
- 顺序固定
- 不得追加第 5 段说明、推荐、菜单、销售式引导
- 用户回复 `1` / `选 2` / `要 3` / `4` 直接按上下文承接，不再确认

---

## 11. 参考资料读取顺序

需要校准 `xuanti` 自身的题感边界时，按这个顺序读：
1. `references/user-profile.md`（最优先，决定这一轮怎么出）
2. `references/evolution.md`（已验证的方法）
3. `references/anti-patterns.md`（已验证的雷区）
4. `references/style-guide.md`（沉淀的通用风格）
